# 在线衣橱与典藏卡光效升级实施计划

## 阶段 1：兼容的数据底层

1. 扩展衣橱类型，加入 v2 目录、资源层、动画原语、主体安全区、最低客户端能力和通用累计条件规则。
2. 新增严格的 v2 目录校验与 URL 归一化，读取顺序为 v2 远程、v2 缓存、v1 远程、v1 缓存、内置创始内容。
3. 保留现有 v1 逻辑和稳定商品 ID，确保旧版本永远不会读取 v2 目录。
4. 为目录校验、回退、版本合并和恶意参数裁剪增加单元测试。

## 阶段 2：资源下载与状态恢复

1. 将单素材下载器扩展为按资源 ID 缓存多个图层，逐文件校验大小和 SHA-256。
2. 下载失败保留上一个已校验版本；已穿戴素材优先保留。
3. 备份继续只保存拥有 ID 和穿戴 ID，恢复后按目录重新下载。
4. 补充多资源下载、旧缓存兼容和失败不扣金币测试。

## 阶段 3：通用视觉运行时

1. 把头像舞台拆成背景层、背景特效、头像、框、挂件、前景特效、昵称与称号。
2. 实现 image、particle、orbit、light-sweep、glow、sprite、text-effect、pointer-parallax 和 click-burst 白名单原语。
3. 加入主体安全区、参数裁剪、动画暂停、减少动态效果和低性能降级。
4. 改造试穿卡片，使在线缩略图、动态预览、金币购买和条件领取保持一致。
5. 用组件与端到端页面检查验证鼠标、键盘、点击、切页和窄窗口行为。

## 阶段 4：20 件首发装扮

1. 生成并审核 5 个头像框、4 个背景、3 个挂件的透明或完整 WebP 素材。
2. 用通用原语配置 5 个动态特效和 3 个动态称号。
3. 建立 `/wardrobe/v2/catalog.json`，写入确认后的 14:6 风格比例、14:6 获取比例、价格和累计条件。
4. 为每个文件生成大小与 SHA-256，并生成轻量缩略图。
5. 将 v2 素材放入 `cloud-assets-source/wardrobe/v2`，不进入安装包。

## 阶段 5：典藏卡分层和光效

1. 保持芙宁娜 v1 原素材不变，以其背景、角色和文字分层作为基准。
2. 为 10 张新卡制作严格对齐的背景、角色、前景效果和文字层，禁止完整卡面与不对齐角色重复叠加。
3. 升级卡片运行时：属性化扫光、边框跑光、轮廓光、粒子、点击爆闪和鼠标速度响应。
4. 加入脸部安全区和效果强度上限，静止时自动收敛。
5. 更新云端卡片目录版本并保留旧卡拥有状态。

## 阶段 6：构建、迁移与发布验证

1. 运行类型检查、单元测试、资源校验和生产构建。
2. 验证老用户升级、新用户初始化、旧备份恢复、离线启动和素材下载失败路径。
3. 验证 Windows 安装包体积，确认 20 件云端素材不进入安装包。
4. 在内置浏览窗口逐类检查 20 件装扮与全部典藏卡的动态表现。
5. 保存 Cloudflare 旧版快照，部署静态资源并逐文件在线回读校验。
6. 发版前向用户汇总实际变更、安装包体积和已知边界；未获得最终发版确认前不发布安装包。
