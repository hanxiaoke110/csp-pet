# 智子拖动稳定性检查（暂未发布）

## 反馈依据

检查用户提供的 `20261010_215020.mp4`（24.4 秒）。录屏中智子动画和点击气泡正常，但没有正常跟随拖动，底层页面出现文字选择。仅凭视频无法读取鼠标按键状态，也不能确认具体 Windows 原生事件丢失点。

代码发现风险：150ms 穿透命中采样可能错过快速按下；拖动仅依赖 document mousemove/mouseup，没有指针捕获或取消、失焦清理。不能声称这就是录屏的唯一根因，也不能据此判断所有设备都会出现。

## 本轮修改

- 使用 Pointer Events 和指针捕获；保留 document 捕获阶段监听作为兼容兜底。
- 松手、pointercancel、lostpointercapture、窗口失焦、页面隐藏、后续事件报告左键已松开时终止拖动，避免残留交互锁。
- 保留 5px 拖动门槛、单击气泡、双击回位，拖动后清除旧双击时间。
- 操作条按钮不启动拖动，智子区域禁止文字选择及浏览器原生拖放。
- 鼠标命中采样由 150ms 调整为 50ms，DPI 查询限为每秒一次；仍保留 120ms 退出穿透防抖，不在每帧反复切换原生窗口状态。
- 漫游时从当前显示位置开始拖动并暂停漫游；拖动不移动透明 OS 窗口，不新增 WebView。
- 同步记录位置引用，松手最终坐标立即保存，避免保存上一次 React 渲染的位置。
- 沿用原有位置存档键及 v3 格式，不调整学生钱包、智子所有权和备份结构。

## 验证及限制

- 拖动控制器专项测试：9 项通过。
- 全量测试：72 个文件、462 项通过。
- TypeScript 检查及主程序生产构建通过（包含 pet 窗口入口）。
- 测试使用模拟事件和捕获目标，不代表 Windows 透明窗口、WebView2 合成器已经实机验证。
- 50ms 采样缩短但不能彻底消除从穿透状态快速按下的时间窗口；指针捕获也不能补回原本未收到的 pointerdown。

发版前仍需在 Windows 验证：快移快拖、悬停后拖动、快速往返、多次松手重新拖、移出精灵/屏幕边缘、Alt+Tab 及取消、多智子、漫游中拖动、125%/150% DPI、双屏、底层页面文字选择和点击穿透、按钮及单/双击、重新启动后位置恢复。同时观察资源占用与是否出现黑屏。
