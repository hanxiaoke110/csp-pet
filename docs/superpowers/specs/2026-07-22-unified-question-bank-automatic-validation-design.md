# 统一题库与自动可靠性验证设计

## 1. 背景

当前项目存在三套主要题库文件和多套加载逻辑：

- 日常选择题与超级挑战读取 `unified-quiz-bank.json`。
- CSP-J/S 真题训练读取 `csp-exam-bank.json`。
- 智子试炼场保留 `dungeon-exam-bank.json`，并叠加统一题库修订。

同一道题可能在不同数据文件中重复存在，题型字段、答案、解析、图片和缓存版本可能不同。教师端修订无法天然保证四个入口同步，旧缓存也可能继续展示错误图片或旧答案。

本设计将题库收敛为一个权威数据源，通过全自动验证产生四个只读投放分片。新版客户端内置最新已验证题库，本地优先加载，云端只负责后续热更新。可靠性流程不依赖人工逐题审核；机器无法确认的题自动隔离。

## 2. 目标

1. 同一道题只维护一份题干、代码、选项、答案和解析。
2. 日常选择题、超级挑战、CSP-J/S 真题和智子试炼场共享同一修订号。
3. 自动发现残缺题、错图、答案冲突、解析矛盾和跨入口不一致。
4. 只有自动验证通过的题能进入学生端。
5. Gitee 或 Cloudflare 不可用时，孩子仍能正常练习。
6. 通过发布新版完成正式切换，同时保留一个版本周期的回滚能力。

## 3. 非目标

- 不要求一次性恢复或发布所有历史题目。
- 不要求人工确认每一道争议题。
- 不在学生客户端执行 AI 验证、编译沙箱或网络爬取。
- 不把四个入口改造成相同玩法或相同界面。
- 不允许 AI 自动改写官方原题后将其冒充真题。

## 4. 总体架构

题库处理链路分为五层：

1. **原始资料层**：保存官方 PDF、网页快照、二手来源和导入记录，不直接提供给客户端。
2. **标准化题库层**：统一题目字段、题型、父子题结构和稳定 ID。
3. **自动验证层**：执行结构检测、来源匹配、确定性求解、模型复核和展示检测。
4. **发布层**：只从 `auto_verified` 题目生成入口分片和试卷清单。
5. **客户端层**：从安装包或本地缓存读取发布分片，后台检查新版本。

Gitee继续作为版本文件、发布分片和原始资料的免费更新源。Cloudflare Worker/D1保存教师修订、验证记录、隔离状态和修订号，并缓存发布结果。客户端不得把 Gitee 或 Cloudflare 作为启动和答题的强依赖。

## 5. 权威题目模型

每道标准化题目至少包含：

```text
id
source
year
examDate
examGroup
level
originalNumber
questionType
question
code
assets
options
correctIndex
subQuestions
blanks
explanation
knowledgePoint
difficulty
provenance
contentHash
verificationStatus
verificationScore
verificationEvidence
```

### 5.1 稳定 ID

ID由来源、考试时间、组别、级别和原始题号组成。题目修订不得改变 ID。无法确认来源的旧题保留原 ID，但标记相应来源等级。

### 5.2 原题与修订

原始题面保持不可变。OCR修复、答案修正和解析补充保存为覆盖层。学生端读取合并结果，教师端能查看修改历史和原始内容。

### 5.3 内容哈希

`contentHash`覆盖题干、代码、图片引用、选项、答案和子题结构。任一字段改变后，旧验证证据立即失效，题目重新进入自动验证流程。

`verificationScore`用于教师端排序和诊断，不作为单独的发布阈值。是否发布只由明确的证据组合和阻断规则决定，避免通过调整分数掩盖强证据冲突。

### 5.4 来源等级

```text
official_exact     已与官方题面和答案自动匹配
official_unlinked  声称来自官方试卷但尚未定位
secondary          来自转载或第三方题库
reconstructed      来自 OCR、截图或网页结构恢复
generated          AI 或规则生成内容
```

来源等级不直接决定是否发布，但会影响验证所需证据。`generated` 内容不得进入 CSP-J/S 历年真题清单。

## 6. 自动验证系统

### 6.1 结构验证

全量检查以下问题：

- ID为空或重复。
- 题干为空、选项为空或答案越界。
- 题干引用代码、程序、横线或图片，但上下文缺失。
- 阅读题子问题、程序填空位置和答案数量不一致。
- 图片不存在、包含邻题、答案或解析。
- OCR乱码、HTML残片和明显拼接错误。
- J/S/GESP、年份、级别和题型字段不合法。
- 同一ID在不同旧题库中的核心字段不一致。

任何阻断错误都将题目标记为 `broken`，不进入后续发布。

### 6.2 来源自动匹配

验证服务自动下载或读取已有官方资料，通过考试时间、题号、题干、代码和选项相似度定位原题，并独立解析官方答案表。匹配结果记录URL、页码、题号、来源哈希和相似度。

无法匹配官方资料不等于自动失败，题目仍可通过更强的确定性求解和多路复核获得练习资格，但不能被标记为官方历年真题。

### 6.3 确定性验证

- 可执行代码题在隔离沙箱中编译运行。
- 输入固定的题目比较实际输出和选项。
- 数学、进制、逻辑、排序和数据结构题使用专用求解器复算。
- 出现未定义行为、缺失输入或多解时自动隔离。
- 代码片段无法安全补齐为完整程序时，不伪造运行结果。

### 6.4 模型陪审团

至少执行三个互不共享中间答案的角色：

1. 解题器A不查看题库答案，独立求解。
2. 解题器B不查看A的结论，独立求解并检查歧义。
3. 批判器检查题面完整性、候选答案和解析是否一致。

使用同一模型时必须采用独立上下文、不同提示角色和顺序扰动。模型共识只能作为中等证据，不能覆盖官方答案或确定性运行结果。

### 6.5 自动裁决

题目状态只有以下四种：

```text
auto_verified  自动验证通过，可以投放
auto_probable  证据不足，暂不投放
disputed       强证据冲突，自动隔离
broken         题目残缺，自动隔离
```

发布条件为：结构验证通过，并满足以下任一证据组合：

- 官方题面与官方答案匹配成功。
- 确定性运行/求解结果、题库答案和两个独立模型结论一致。
- 知识题获得两个可信来源支持，且两个独立模型结论一致。

官方答案与确定性结果冲突、模型之间冲突或题面存在多解时，不进行自动修正，直接标记 `disputed`。

### 6.6 解析验证

解析只在答案锁定后生成或修订。独立批判器检查：

- 解析能否推出正确选项。
- 解析中的字母、数值和代码结果是否对应 `correctIndex`。
- 解析是否引用题面不存在的变量或条件。
- 解析是否只有“官方答案为X”而没有推理。

解析不合格时，题目可重新生成解析；连续失败则保持不发布。

## 7. 四个入口的投放规则

### 7.1 日常选择题

仅使用 `source=gesp`、`questionType=choice` 且 `verificationStatus=auto_verified` 的题目。按学生阶段、知识点和薄弱点抽题，避免短期重复。

### 7.2 超级挑战

使用 CSP-J 程序阅读和程序填空题。必须保留完整程序、父题和全部子问题，不将单个子题脱离上下文转换成普通选择题。

### 7.3 CSP-J/S 真题

通过 `exam-manifests.json` 保存年份、组别、试卷、原始题号和顺序。只有成功匹配官方试卷的题可以进入历年真题清单。题型练习可以使用同一清单的过滤视图。

### 7.4 智子试炼场

- 普通技能使用 GESP 1-4 级选择题和较短的 CSP-J 基础选择题。
- 大招和 Boss 使用 CSP-J 程序阅读或程序填空题。
- 疗伤模式根据薄弱知识点选择短题。
- 自动排除整页截图、超长题、缺上下文题、争议题和不适合当前战斗节奏的题。

## 8. 发布产物

统一题库是唯一可编辑数据源，以下文件均由发布脚本自动生成：

```text
question-manifest.json
daily-gesp.json
super-cspj.json
exam-manifests.json
exam-questions.json
dungeon-mixed.json
verification-summary.json
```

生成文件禁止人工编辑。每个文件包含内容修订号、验证修订号、规则修订号、题目数量和SHA-256哈希。

## 9. 新版客户端加载策略

### 9.1 安装包内置

新版发布前运行自动验证和分片生成，将最新已验证题库直接放入安装包。首次启动不需要联网下载题库。

### 9.2 缓存优先级

加载顺序为：

1. 本地已验证的较新缓存。
2. 安装包内置的已验证题库。
3. 上一版有效缓存。

客户端使用新的缓存命名空间，例如 `question_bank_v2`。只有云端修订号高于本地且下载文件通过哈希和结构校验时，才能原子替换缓存。

旧的 `csp-exam-bank.json` 和 `dungeon-exam-bank.json` 不作为新版客户端的故障兜底，避免重新暴露未经统一验证的题目。它们仅在迁移期继续服务尚未升级的旧客户端。

### 9.3 后台更新

客户端启动后后台请求小型 `question-manifest.json`。版本未变化时不下载题库；版本变化时只下载需要的入口分片。下载、Gitee或Cloudflare失败不影响当前练习。

一次练习或战斗固定使用启动时的题库修订号。新版本在下一轮练习生效，避免作答过程中题目或答案变化。

## 10. 迁移和完全切换

1. 建立权威模型、自动验证器和分片生成器。
2. 在不影响旧客户端的情况下进行影子运行，对比新旧题数和答案。
3. 自动执行四个入口的端到端测试。
4. 发布内置统一题库的新客户端，四个入口同时改用统一加载服务。
5. 旧Gitee题库文件继续保留，服务尚未升级的客户端。
6. 下一桌面版本发布后，自动监控确认四个入口各完成至少1000轮无P0异常练习，再删除旧加载代码；旧数据文件继续作为历史归档。

完全切换不要求所有旧题都通过验证。无法确认的题自动隔离；只要四个入口有足够的 `auto_verified` 题并通过发布门槛，即可切换。

## 11. 测试设计

### 11.1 数据测试

- 全题库结构验证。
- 跨旧题库重复ID和字段差异检测。
- 父子题、答案和填空位置一致性检测。
- 图片文件、图片尺寸和答案泄露检测。
- 发布分片只包含 `auto_verified` 题。

### 11.2 规则测试

- 日常题只包含GESP选择题。
- 超级挑战只包含完整的CSP-J阅读/填空题。
- 真题清单保持组别、年份、题号和顺序。
- 试炼场普通技能、Boss和疗伤题符合各自限制。

### 11.3 客户端端到端测试

每个入口至少自动模拟1000轮，覆盖：

- 普通题、长选项、代码题、流程图、多小题和填空题。
- 在线、离线、慢网、下载中断、错误哈希和缓存损坏。
- Gitee不可用、Cloudflare不可用和两者同时不可用。
- 版本升级、版本回滚和练习中途收到新版本。
- 桌面常用尺寸和最小支持窗口尺寸。

### 11.4 发布门槛

- 结构阻断错误为0。
- 答案越界为0。
- 错页或答案泄露图片为0。
- 跨入口同ID核心字段差异为0。
- 隔离题进入发布分片的数量为0。
- 所有分片哈希校验通过。
- 四个入口使用同一组修订号。
- 离线和双远端故障场景仍可开始并完成练习。

## 12. 监控和回滚

客户端记录不含个人答案内容的题库运行指标：加载来源、修订号、缓存校验结果、空题、渲染失败和题目报错次数。教师端显示各入口可用题数、隔离题数和最近发布时间。

发布清单保留上一版分片和哈希。新版本出现结构错误、异常率上升或文件无法读取时，客户端自动回退上一版有效缓存；服务端可以将清单指向上一修订，无需重新发布客户端。

## 13. 验收标准

1. 四个入口均通过统一题库服务获取题目。
2. `csp-exam-bank.json`和`dungeon-exam-bank.json`不再作为正常运行数据源。
3. 新安装、升级安装和离线启动都能立即练习。
4. 题目修订后四个入口在下一轮练习读取相同内容。
5. 未验证、争议和残缺题无法进入学生端。
6. Gitee和Cloudflare同时不可用时，客户端仍能使用内置或上一版题库完成练习。
