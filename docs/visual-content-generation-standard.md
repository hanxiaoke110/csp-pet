# 智子学习资料视觉生成标准

> 版本：1.1  
> 日期：2026-07-11  
> 适用范围：P1-P71 课程讲义、AI 寓言、知识点救援、飞书学习资料、智子试炼场视觉素材。

## 1. 最终结论

每节课不固定生产四张卡，也不要求所有课程都生成相同数量的图片。

标准配置为：

- 普通课程：1 张寓言记忆卡或 1 张知识总览卡。
- 核心课程：1 张寓言记忆卡 + 1 张知识总览卡。
- 高频难点：在上述基础上，允许增加 1 张专项易错卡。
- 练习题使用客户端题库和飞书正文，不生成题目截图。

P62、P69 属于核心课程，采用两张卡：

1. 寓言记忆卡：负责兴趣、直觉和记忆。
2. 知识总览卡：负责完整、准确、可复习的知识结构。

## 2. 两类卡片必须分工

### 2.1 寓言记忆卡

目标不是讲完整知识，而是让孩子愿意看，并在做题时想起一个具体场景。

必须包含：

- 一个明确的故事冲突。
- 一个行动或规则带来的结果。
- 一个知识反转或顿悟。
- 一句不超过 24 个汉字的记忆口诀。
- 智子小麒麟作为陪伴者、提问者或点拨者。

最终采用“六格或九格漫画承载三幕剧情”。六格适合动作简单、知识点单一的课程；九格适合需要展示反转、边界条件或多一步顿悟的课程，但仍必须保持三幕清楚、文字克制。

| 剧情阶段 | 对应漫画格 | 作用 | 示例 |
|---|---|---|---|
| 第一幕：遇到麻烦 | 六格第 1-2 格；九格第 1-3 格 | 建立任务并提出问题 | P69 学徒想从缸底直接拿碗 |
| 第二幕：错误尝试 | 六格第 3-4 格；九格第 4-6 格 | 展示失败后果，智子进行点拨 | 上层碗倒塌，说明不能跨过栈顶 |
| 第三幕：发现规则 | 六格第 5-6 格；九格第 7-9 格 | 正确解决并形成记忆 | 只从顶部放、只从顶部取 |

寓言卡的文字总量控制在 80-140 个汉字，不放完整代码、复杂度和全部易错点。第 6 格或底部知识揭示区允许出现 1-3 个关键操作名、一个简图和一句口诀。

趣味性要求：

- 场景中必须发生一件事，不能只是角色站着讲课。
- 必须有表情变化：困惑、尝试、意外、理解或成功。
- 可以有轻微夸张和漫画拟声，但不能喧宾夺主。
- 智子不能只做角落装饰，应提出问题或完成点拨。
- 不使用公司名、机构名、品牌、二维码、网址和水印。

### 2.2 知识总览卡

目标是让孩子在 3-5 分钟内完成一次完整复习。知识密度应明显高于当前纯生图版本。

每张总览卡必须覆盖以下七项中的至少六项：

1. 这是什么：一句话定义。
2. 核心模型：结构图、流程图或状态变化。
3. 最小代码：3-8 行，或 1-3 个关键 API。
4. 运行示例：输入、状态变化、输出或表格。
5. 什么时候使用：适用条件与限制。
6. 复杂度或规则：时间、空间、边界。
7. 易错点与自测：2-3 个易错点 + 1 个一分钟问题。

知识总览卡不由 AI 直接生成全部文字和代码。标准流程是：

```text
教案/讲义/题库提取内容
→ 人工确认知识脚本
→ AI 生成智子和局部插画
→ HTML/CSS 或其他确定性模板排版文字、代码、表格
→ 导出 PNG
→ OCR、代码和移动端检查
```

AI 只负责：

- 智子小麒麟表情和动作。
- 寓言场景、知识隐喻和局部装饰。
- 不含关键文字的背景和视觉元素。

程序化排版负责：

- 标题、中文正文和口诀。
- C++ 代码与运算符。
- 表格、数组、栈、队列和流程箭头。
- 复杂度、边界条件和自测题。

这样可以避免乱码、代码错误、重复文字、运算符丢失和版式漂移。

## 3. 知识总览卡统一版式

### 3.1 画布与网格

- 主画布：1024 × 1536，竖版 2:3。
- 安全边距：左右 56 px，上下 48 px。
- 栅格：12 列，模块间距 20-24 px。
- 卡片圆角：8 px 以内。
- 正文区域不能被角色、装饰或标题遮挡。

### 3.2 页面结构

| 区域 | 高度占比 | 内容 |
|---|---:|---|
| 标题区 | 10%-12% | P 课号、知识点标题、一句话目标 |
| 核心图解区 | 30%-35% | 结构、流程、状态变化或运行示例 |
| 知识模块区 | 38%-42% | 定义、代码、应用、复杂度、易错点 |
| 自测与口诀区 | 10%-12% | 一分钟自测、记忆口诀 |

### 3.3 字号与文字量

- 主标题：64-76 px。
- 模块标题：34-40 px。
- 正文：27-32 px。
- 代码：26-30 px，使用等宽字体。
- 一张卡总文字量建议 180-320 个汉字，不超过 380 个汉字。
- 每个段落不超过 3 行，每行不超过 18-22 个汉字。
- 代码只放最小示例，不在图中放整道题答案。

### 3.4 内容模板

```text
Pxx 知识点｜知识总览
一句话目标

1. 核心概念
2. 结构或流程图
3. 最小代码/API
4. 运行示例
5. 适用条件/常见应用
6. 复杂度/边界
7. 易错提醒
8. 一分钟自测
9. 记忆口诀
```

## 4. 寓言卡统一版式

### 4.1 画布与叙事

- 主画布：1024 × 1536，竖版 2:3。
- 建议六格或九格漫画；轻量课程可用一张主场景 + 两个小场景。
- 主角行动必须清楚，不能只靠文字解释发生了什么。
- 每个场景只承担一个动作，阅读方向保持从上到下或从左到右。

### 4.2 页面结构

| 区域 | 内容 |
|---|---|
| 标题 | P 课号 + 寓言标题 |
| 第一幕 | 问题或任务出现 |
| 第二幕 | 错误尝试、困难或冲突 |
| 第三幕 | 发现算法规则并解决问题 |
| 底部 | 知识点名称 + 一句口诀 + 打开详细讲义提示 |

### 4.3 趣味标准

- 至少有一次明显的表情变化。
- 至少有一个可视化后果，例如碗倒塌、粮袋堆积、路线走错。
- 智子必须参与剧情：提问、提醒、演示或庆祝。
- 可以使用 1-2 个漫画拟声词，如“哗啦”“叮”“咔嗒”，但不使用网络烂梗。
- 结尾要让孩子感到“原来如此”，不能只复述定义。

## 5. 智子小麒麟角色规范

角色基准使用当前软件 Logo 和 `zhizi-character-sheet-v1.png`。智子是 P1-P71 唯一固定主角，不再设置“小六”“阿短”或其他长期学生角色。

必须保持：

- 奶油白毛发。
- 粉色耳朵和角部细节。
- 浅金色装饰与额头纹样。
- 圆润幼麒麟轮廓。
- 温和、聪明、陪伴型气质。

教学状态固定为：

- 开心欢迎。
- 认真思考。
- 指向知识点。
- 发现错误。
- 鼓励学生。
- 挑战成功。

使用规则：

- 总览卡中角色面积不超过画面的 12%-18%。
- 寓言卡中角色可以达到 20%-30%，但必须服务剧情。
- 总览卡同一页可出现 1-3 个小型智子讲解贴纸；寓言六格或九格中智子可按剧情重复出现，但每格最多一个。
- 不允许每张图改变毛色、角数、脸型、尾巴或饰品。
- 不增加狐狸、CPU 机器人等新的主讲角色；知识物品可以拟人化，但不能取代智子。

### 5.1 寓言连续剧情规则

P1-P71 使用轻连续剧情，不要求孩子按顺序阅读：

- 智子携带“智慧星图”旅行，每节来到一个新地点。
- 当地人物只在本课出现，例如学徒、掌柜、工匠、管理员。
- 阅读资料的孩子用第二人称“你”参与思考，不另起固定姓名。
- 每节课 90% 内容独立，最多 10% 用道具、地点或一句台词连接前后课。
- 开场连接不超过 30 字，下一站线索不超过 20 字。
- 完成本课后，智子获得知识碎片、徽章或下一站线索，可复用现有成就和试炼场体系。

统一叙事结构：

```text
智子来到新地点
→ 遇到当地人物和困难
→ 邀请“你”一起思考
→ 错误尝试产生可见后果
→ 智子点拨算法规则
→ 获得知识碎片和下一站线索
```

## 6. 视觉风格

### 6.1 配色

- 主色：青蓝、蓝色。
- 知识/正确：绿色。
- 重点/奖励：黄色、浅金色。
- 错误/警告：珊瑚红，仅用于提醒。
- 背景：白色、浅灰蓝或极浅暖色。

避免整张图被单一紫色、深蓝色、米黄色或棕色占满。

### 6.2 图形语言

- 漫画教材信息图 + 编程冒险 UI，不使用管理后台式规整白卡。
- 背景使用轻微暖白纸纹，保持干净，不做仿旧污渍。
- 模块允许轻微错位、纸胶带、便签、对话气泡和手绘边框，形成儿童编程杂志质感。
- 代码使用高对比黑底代码板，中文、代码和表格必须确定性排版。
- 模块编号使用统一的珊瑚红圆标；知识、正确、警告和自测保持稳定配色语义。
- 线条清楚，图标和箭头含义明确。
- 不使用模糊、过暗、纯氛围型图片。
- 不使用嵌套卡片和过多装饰边框。
- 装饰不能挤压代码、表格和正文。

## 7. P62 与 P69 的最终内容规格

### 7.1 P62 计数排序

寓言卡：

- 第一幕：学徒反复搬粮袋比较大小，越来越累。
- 第二幕：智子让他把 1-6 号粮袋放进对应格子。
- 第三幕：按格子顺序搬出，粮袋自然有序。
- 反转：编号范围达到一百万，空格子太多，方法不再划算。
- 口诀：不比大小，先数个数；值域小才划算。

知识总览卡：

- 定义：统计每个值出现次数后按值输出。
- 最小代码：`cnt[a[i]]++` 与双层输出循环。
- 运行示例：`3 1 2 3 0 1` → `cnt=[1,2,1,2]` → `0 1 1 2 3 3`。
- 适用：整数、值域较小。
- 复杂度：`O(n + m)`，空间 `O(m)`。
- 易错：未初始化、数组越界、负数未偏移、值域过大。
- 自测：100 个数分布在 0 到 1 亿，是否适合计数排序？

### 7.2 P69 栈

寓言卡：

- 第 1 格：面馆把青、红、黄碗依次放入深口缸。
- 第 2 格：学徒想直接取缸底青边碗，智子提出问题。
- 第 3 格：强行伸手导致上层碗“哗啦”倾斜碰撞。
- 第 4 格：智子指出只能操作最上面的碗。
- 第 5 格：依次取出黄、红、青碗，学徒理解规则。
- 第 6 格：空缸判空提醒，底部揭示 `push/pop/top`。
- 口诀：只碰栈顶，后进先出；取前判空。

知识总览卡：

- 定义：只能在一端进行插入和删除的线性结构。
- 操作：`push`、`pop`、`top`、`empty`、`size`。
- 状态示例：A、B、C 依次入栈，第一次 `pop` 得到 C。
- 最小代码：C++ `stack<int>` 的 5-7 行示例。
- 应用：括号匹配、表达式求值、函数调用、DFS。
- 复杂度：常见栈顶操作 `O(1)`。
- 易错：空栈 `top/pop`、把栈当队列、试图访问中间元素。
- 自测：A、B、C 依次入栈，再出栈两次，栈顶是谁？

## 8. 标准制作流程

每张卡按以下顺序制作：

1. 读取对应教案、讲义、寓言和题库。
2. 形成内容脚本，标明每个结论的来源。
3. 教学审校：检查定义、代码、答案、复杂度和边界。
4. 生成智子角色或寓言场景，不生成关键文字。
5. 使用统一模板排版准确文字、代码、表格和箭头。
6. 导出 PNG，并保留可编辑源文件。
7. 执行 OCR 与人工逐字检查。
8. 在 1024×1536、桌宠窄窗口和手机飞书中检查。
9. 上传飞书，重新读取确认图片块存在。
10. 基础资料保持公开只读；班级资料保持非公开。

## 9. 验收门槛

### 内容

- [ ] 定义、代码、复杂度和答案均经过人工核对。
- [ ] 图片文字与飞书正文没有冲突。
- [ ] 没有公司、机构、二维码、网址和水印。
- [ ] 每张图只有一个主要学习目标。

### 视觉

- [ ] 智子外观与角色设定一致。
- [ ] 缩小到 50% 后仍能读清标题和模块标题。
- [ ] 文字、角色、代码、箭头互不遮挡。
- [ ] 颜色对比足够，红色只用于错误。

### 技术

- [ ] 文件为 1024×1536 PNG 或高质量 WebP。
- [ ] 文件名包含课号、类型和版本号。
- [ ] 飞书页面公开状态符合资源权限。
- [ ] 客户端只引用飞书链接，不把大图打进安装包。

## 11. P69 v3 候选基准

P69 v3 是当前唯一候选批量模板，等待最终人工确认：

- 寓言卡：六格或九格漫画，包含问题、错误尝试、可见后果、智子点拨、正确解决和知识揭示。
- 知识总览卡：暖白纸纹、彩色编号、轻微错位纸卡、胶带、黑底代码板、状态图、应用标签、陷阱、做题方法和自测。
- 寓言卡由内置生图生成，使用智子角色设定作为参考。
- 总览卡由 HTML/CSS 确定性排版后，经 Playwright 以 1024×1536 导出。
- P69 v3 当前仅保存在本地，尚未替换飞书中的 v2；必须由用户最终确认后才更新飞书。
- P62 暂不制作 v3；P69 v3 确认后，才将同一模板和质量标准复制到 P62 及其他核心课程。

## 12. 批量生产红线

- 未通过 P69 v3 最终验证前，不批量生成 P1-P71。
- 不直接使用纯 AI 生成的知识总览卡作为正式成品。
- 不因追求信息密度而把字号压到手机端不可读。
- 不把寓言卡变成知识总览卡；寓言负责故事，总览负责完整复习。
- 不上传未检查文字、代码、顺序、箭头和遮挡的图片。
- 不覆盖旧文件；所有新版本使用递增版本号，飞书替换后仍保留本地历史稿。
