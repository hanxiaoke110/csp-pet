# 许愿复投修复与 7 天间隔

2026-10-24 经用户要求，将同一设备对同一愿望的复投间隔从 14 天改为 7 天。每次成功投票仍消耗 1 张许愿票，跨教师限制不变，典藏卡人气投票不受影响。

线上旧 votes 表带有内置 UNIQUE(wish_id,device_hash)。v12 仅移除了命名索引，没有解除 SQLite 自动索引，因此到期复投会触发唯一约束而返回 500。v13 用 D1 原子 batch 重建投票历史表，保留所有历史 ID、设备、班级、时间；按最新历史投票时间加 7 天重新计算已有冷却，保留愿望排行榜总票数。对没有历史的冷却记录只缩短原等待 7 天，版本标记保证不会重复缩短。

验证：真实旧表结构回归、6/8/15 天场景、冷启动幂等、迁移整体回滚、并发防重与扣票等 74 项测试通过，TypeScript 检查通过。本地 D1 导入发布前私有备份后，用合成账号完成到期可投、未到期拒绝验证。

服务端版本 `909c62df-aa2a-4ae4-993d-3355a53d6304`，schema 13。线上回读确认 306 条旧历史逐字段一致、183 条愿望保留、永久唯一锁为零、历史冷却规则偏差为零，未使用真实学生账号投测试票。健康、工坊、排行榜、典藏卡投票配置返回 200 JSON。

发布前私有 SQL 备份存放 artifacts/private/wishes-2026-10-24/before.sql（gitignored，权限 600）。复核脚本 scripts/verify-wish-vote-release.mjs 只读且不打印身份记录。

本次未发布桌面安装包。旧客户端根据服务端 next_vote_at 实际执行 7 天间隔，重新进入许愿页会获取新冷却时间；规则页静态“14 天”仍需下次客户端发版替换。源代码中说明已改为 7 天。
