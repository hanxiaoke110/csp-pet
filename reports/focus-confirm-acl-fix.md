# 专注提前结束确认弹窗修复

日期：2026-10-14（Asia/Shanghai）。状态：代码修复、验证完成，未发布新安装包。

## 根因

v1.7.50 的 FocusPage 仍调用同步形式的 window.confirm。随桌面插件 2.7.1 注入后，该函数变成 Promise 并转发到未注册的 plugin:dialog|confirm。Promise 被当作真值，专注立即进入复盘；拒绝又被全局错误处理器追加为红条，离开页面后仍显示。

此前 v1.7.37 修复覆盖试炼场，但没有阻止新增模块重新引入同类调用。旧专注测试仅验证静态按钮渲染。

## 本次修复

- 复用现有应用内确认弹窗，不调用原生 dialog，不放宽桌面权限。
- 取消保留原会话；确认进入复盘，保留累计时间，仍由学生选择是否保存。
- 弹窗绑定会话 ID，计时自然结束或新会话开始后，不会误结束下一场。
- AST 检查覆盖 src、src-dungeon 的原生 confirm 引用、导入和直接插件命令；测试文件与独立教师网页不属于桌面运行时。
- 检查接入主程序和试炼场 build；现有发布 CI 的 npm test、npm run build 自动执行门禁。
- 新增 jsdom 仅用于测试，属于开发依赖，不进入安装包。
